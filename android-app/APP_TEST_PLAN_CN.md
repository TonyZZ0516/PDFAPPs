# SwiftPDF Android App 测试方案

更新日期：2026-05-22

## 1. 测试目标

本方案用于验证 SwiftPDF Android App 是否达到当前 MVP 的可交付标准，重点分为两类：

1. UI 还原度测试：确认 Android 实现是否贴近高保真设计稿、交互预期和视觉规范。
2. 功能测试：确认核心流程是否可用、稳定、无明显阻塞和崩溃。

当前阶段的验收原则是：先保证主流程闭环，再逐步提高 UI 精度和高级功能完整度。

## 2. 测试范围

### 当前必须覆盖

- Home：首页、最近文件、导入 PDF、空状态。
- Reader：PDF 打开、页面预览、页码、当前文档状态。
- Scan：相机权限、相机预览、拍摄页面、导出扫描 PDF。
- Export：当前文档展示、系统分享。
- Settings：最近文件数量、清空历史、版本和存储说明。
- Bottom Navigation：首页、阅读、扫描、导出、设置之间切换。

### 当前暂不作为阻塞项

- OCR。
- PDF 压缩、合并、拆分。
- PDF 搜索、缩放、书签、批注。
- 图片裁剪、旋转、增强。
- Pro 订阅和支付。
- 多设备、多账号、云同步。

这些功能可以保留入口或占位，但不能影响已完成主流程。

## 3. 测试环境

### 推荐环境

- Android Studio：Panda 4 或当前本机版本。
- Gradle：项目自带 Wrapper。
- JDK：Android Studio JBR。
- 模拟器：Pixel 7 / API 36 / x86_64。
- 测试文件：
  - 小型 1 页 PDF。
  - 多页 PDF。
  - 文件名较长的 PDF。
  - 中文文件名 PDF。
  - 损坏 PDF。
  - 扫描导出的 PDF。

### 必跑命令

```powershell
$env:JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT="$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat :app:assembleDebug --stacktrace
.\gradlew.bat :app:testDebugUnitTest --stacktrace
```

### 真机补充

模拟器通过后，至少使用 1 台真实 Android 手机补测：

- 相机权限和拍摄稳定性。
- 文件选择器兼容性。
- 分享到微信、邮件、Google Drive 或系统文件管理器。
- 不同屏幕尺寸下的文字和按钮显示。

## 4. UI 还原度测试

### 4.1 测试依据

UI 还原度以以下材料为准：

- 高保真设计稿：`pdf-reader-mvp/HI_FI_DESIGN_CN.html`
- 设计规格：`pdf-reader-mvp/DESIGN_SPEC_CN.md`
- Android 当前实现：`android-app/app/src/main/java/com/swiftpdf/app/ui`

如果 Figma 后续成为正式设计源，则以 Figma 为第一优先级，HTML 设计稿作为历史参考。

### 4.2 还原度评分标准

每个页面按 100 分评分：

- 布局结构：25 分
- 字体层级和字号：15 分
- 颜色和视觉风格：15 分
- 间距、圆角、卡片密度：15 分
- 图标和按钮状态：10 分
- 空状态、错误状态、加载状态：10 分
- 动效和交互反馈：10 分

验收建议：

- 90 分以上：可进入发布候选。
- 80-89 分：可继续功能开发，但需要记录 UI 差异。
- 70-79 分：只能内部测试，不建议对外演示。
- 70 分以下：需要优先返工 UI。

### 4.3 页面级检查清单

#### Home

- 页面标题、说明文案、导入入口层级清晰。
- 最近文件列表显示文件名、大小、时间。
- 空状态有明确主操作，不出现 Pro 干扰。
- 文件行点击区域足够大。
- 删除按钮图标清晰，不误触文件打开。
- 长文件名不会挤压删除按钮或溢出屏幕。

#### Reader

- 当前文件名和文件大小显示正确。
- PDF 页面区域比例稳定，不因为加载图片导致布局跳动。
- 页码 `Page X of Y` 清晰。
- 上一页/下一页按钮禁用状态明确。
- 页面滚动时底部导航不遮挡主要内容。
- 加载失败状态有清楚提示，不出现空白死页。

#### Scan

- 权限说明文案清楚，不提前强迫授权。
- 相机预览区域尺寸稳定。
- `Capture Page` 和 `Export Scan to PDF` 主次关系明确。
- 已拍页面列表可读，删除按钮位置一致。
- 导出中、导出失败、无页面不可导出状态要有反馈。

#### Export

- 有当前文档时显示文件名、大小和分享入口。
- 无当前文档时显示明确空状态。
- 分享按钮位置和视觉权重合理。
- 后续压缩、转图片等占位入口不能像已完成能力一样误导用户。

#### Settings

- 最近文件数量显示准确。
- 有历史记录时显示 `Clear History`。
- 无历史记录时隐藏清空按钮或禁用。
- 存储说明、默认质量、版本信息排版清晰。

#### Bottom Navigation

- 五个入口均可点击。
- 当前选中项视觉明显。
- 点击区域不能贴近系统手势区域导致误触。
- 图标和文字对齐。
- 小屏幕下文字不重叠、不截断。

### 4.4 适配测试

至少检查以下尺寸：

- Pixel 7 标准屏。
- 小屏手机，如 360x640 dp。
- 大屏手机，如 412x915 dp。
- 横屏基础检查。

每个尺寸至少截图：

- Home
- Reader
- Scan
- Export
- Settings

### 4.5 UI 缺陷优先级

- P0：界面遮挡导致核心功能无法使用。
- P1：按钮、文字、导航明显错位或误导用户。
- P2：和设计稿有明显差异，但不阻塞主流程。
- P3：细节优化，如间距、圆角、图标风格微调。

## 5. 功能测试

### 5.1 主流程一：导入并阅读 PDF

| 编号 | 用例 | 步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|
| F-001 | App 启动 | 安装后冷启动 App | 进入 Home 或恢复最近文档，无崩溃 | P0 |
| F-002 | 打开文件选择器 | 点击 `Choose PDF` | 打开系统文件选择器 | P0 |
| F-003 | 导入 PDF | 选择 1 个 PDF | 自动进入 Reader | P0 |
| F-004 | 渲染第一页 | 进入 Reader 后等待加载 | 显示 PDF 预览和 `Page 1 of N` | P0 |
| F-005 | 最近文件记录 | 返回 Home | 最近文件顶部显示刚导入 PDF | P0 |
| F-006 | 重启恢复 | 强制关闭后重新打开 App | 最近文件存在，Reader/Export 可恢复当前文档 | P1 |
| F-007 | 最近文件打开 | 点击最近文件行 | 进入 Reader 并渲染该 PDF | P0 |
| F-008 | 删除最近记录 | 点击最近文件删除按钮 | 仅从最近列表移除，不删除原始文件 | P1 |

### 5.2 主流程二：扫描并生成 PDF

| 编号 | 用例 | 步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|
| F-101 | 进入扫描页 | 点击底部 `Scan` | 显示相机权限说明或相机预览 | P0 |
| F-102 | 请求相机权限 | 点击 `Enable Camera` | 弹出系统权限或进入预览 | P0 |
| F-103 | 拒绝权限 | 系统权限选择拒绝 | 页面显示可重试说明，不崩溃 | P1 |
| F-104 | 授权后预览 | 允许相机权限 | 显示 CameraX 预览 | P0 |
| F-105 | 拍摄页面 | 点击 `Capture Page` | 已拍页面数量增加 | P0 |
| F-106 | 删除已拍页面 | 点击页面删除按钮 | 页面从列表移除 | P1 |
| F-107 | 无页面导出 | 未拍页面时查看导出按钮 | `Export Scan to PDF` 禁用 | P0 |
| F-108 | 导出扫描 PDF | 拍摄至少 1 页后点击导出 | 生成 PDF 并自动进入 Reader | P0 |
| F-109 | 导出结果入库 | 返回 Home | 新 PDF 出现在最近文件顶部 | P1 |

### 5.3 主流程三：导出和分享

| 编号 | 用例 | 步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|
| F-201 | 无文档状态 | 未选择文件时进入 Export | 显示无当前文档提示 | P1 |
| F-202 | 有文档状态 | 导入或打开 PDF 后进入 Export | 显示当前文件名、大小、分享按钮 | P0 |
| F-203 | 分享导入 PDF | 点击 `Share PDF` | 打开系统分享面板 | P0 |
| F-204 | 分享扫描 PDF | 扫描导出后点击分享 | 通过 FileProvider 正常分享 | P0 |
| F-205 | 分享取消 | 分享面板按返回 | 回到 App，不丢失当前文档 | P1 |

### 5.4 主流程四：设置和本地状态

| 编号 | 用例 | 步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|
| F-301 | 显示历史数量 | 进入 Settings | 最近文件数量准确 | P1 |
| F-302 | 清空历史 | 点击 `Clear History` | 最近列表清空，原始文件不删除 | P0 |
| F-303 | 清空后 Home | 回到 Home | 显示空状态和导入入口 | P1 |

|---|---|---|---|---|

## 6. 自动化测试建议

### 第一阶段：低成本回归

- 使用 Gradle 编译检查。
- 使用 ViewModel 单元测试验证状态流转。
- 使用 ADB 脚本做主按钮点击冒烟。

建议覆盖：

- App 启动无崩溃。
- `Choose PDF` 能拉起系统 DocumentsUI。
- 底部五个 Tab 可切换。
- 清空历史后 Home 进入空状态。

### 第二阶段：Compose UI Test

为关键组件补充 Compose UI 测试：

- Home 空状态。
- Home 最近文件列表。
- Reader 无文档状态。
- Reader 有文档状态。
- Scan 权限状态。
- Export 有文档/无文档状态。
- Settings 清空按钮状态。

### 第三阶段：端到端测试

引入更完整的设备测试：

- 导入 PDF。
- 打开 Reader。
- 扫描生成 PDF。
- 分享 PDF。
- 重启后恢复最近文档。

## 7. 验收标准

### MVP 内测通过标准

- P0 功能用例 100% 通过。
- P1 功能用例 90% 以上通过。
- 无启动崩溃、无主流程崩溃。
- Home、Reader、Scan、Export、Settings 五个页面均可访问。
- 至少 1 个导入 PDF 和 1 个扫描生成 PDF 可在 Reader 打开。
- UI 还原度平均分不低于 80 分。

### 对外演示通过标准

- P0/P1 功能用例全部通过。
- UI 还原度平均分不低于 90 分。
- 核心流程全程可录屏演示：
  1. 导入 PDF。
  2. 阅读 PDF。
  3. 扫描一页。
  4. 导出 PDF。
  5. 分享 PDF。
  6. 清空历史。

每次测试结束后建议保留：

- 测试日期和 APK 版本。

- P0/P1 缺陷列表。
- 关键页面截图。

## 10. 当前建议下一步

1. 先按本方案完成一轮 MVP 功能测试，把 P0/P1 问题清掉。
2. 再做 UI 还原度评分，确定哪些页面要重新贴近高保真稿。
3. 然后补 Compose UI Test 和 ViewModel 单元测试，避免后续开发反复把主流程改坏。
4. 最后再进入 OCR、压缩、合并、拆分、Pro 等后续模块。
